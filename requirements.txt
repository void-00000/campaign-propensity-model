# ---------------------------------------------------------------------------
# WHY THESE VERSIONS ARE PINNED EXACTLY (==) AND NOT >=
# ---------------------------------------------------------------------------
# These started as ">=" ("this version or newer"), which is the friendlier
# default and is wrong for this project.
#
# The reason is outputs/models/*.joblib. A pickled scikit-learn or XGBoost
# model is COUPLED to the library version that created it -- it stores the
# internal object layout of that specific version. Load a scikit-learn 1.9
# pickle under a future 1.11 and you get an InconsistentVersionWarning at best,
# and a genuine failure at worst.
#
# With ">=", Streamlit Cloud installs whatever is newest ON THE DAY IT BUILDS.
# That day might be six months from now. The app deployed fine today and would
# break later, on its own, with no commit from me -- and I'd find out when
# someone told me my portfolio link was broken. That's the worst failure mode
# there is: silent, delayed, and discovered by someone else.
#
# Pinning means the cloud builds the environment I actually tested, today and
# in a year. The tradeoff is real: pinned dependencies don't pick up security
# patches automatically, so they need occasional deliberate review. For a
# project shipping version-coupled model artifacts, that tradeoff is worth it.
#
# To upgrade deliberately: bump a pin, re-run `python src/run_all.py` to
# regenerate the models under the new version, confirm the metrics still match,
# and commit both together. The models and these pins are one unit.
#
# Versions below are what produced the documented results:
#   AUC 0.8156, top-decile lift 4.71x
# ---------------------------------------------------------------------------
